# Judge Evidence Matrix

This is not the slide order. It is a research tool for making sure the future presentation has visible proof for the official rubric.

| Official criterion | What judges need to understand | Strong evidence type | Presentation failure to avoid |
|---|---|---|---|
| Solution effectiveness & prototype readiness | It addresses Challenge 2 and works end-to-end | concise problem-to-action flow + live/replay demo + real UI | feature claims with no working proof |
| Creativity & innovation | It adds value beyond existing monitoring/threshold alerts | clear contrast with baseline/existing workflow + specific differentiator | saying "AI-powered" as the innovation |
| Scope & effort | Team built substantial work in the hackathon without pretending to build an industry platform | architecture + implemented-vs-future boundary + key engineering depth | giant roadmap presented as finished work |
| Technical execution & feasibility | Data/model/edge/hardware choices are technically defensible | real dataset, model task, validation method, architecture, constraints | jargon wall or unsupported accuracy claims |
| Communication & presentation | Judges can follow the argument and remember it | one-message slides, strong demo narrative, coherent assertion titles | text-heavy report deck |
| Open-source alignment | Others can inspect/reuse/adapt the work | repo/license/data provenance/open interfaces/DPG path | tiny GitHub logo on final slide |
| Sustainability & SDG alignment | Technical behavior plausibly reduces avoidable food loss | causal chain from earlier warning/action to lower loss risk + honest impact framing | fabricated "X% food saved" number |

## Four extra official "How to Win" themes

### Responsible AI
Possible evidence:
- explicit uncertainty/limitations;
- no food-safety claim without validation;
- transparent model/task;
- human-in-the-loop action.

### Societal relevance
Possible evidence:
- real cold-chain problem;
- Qatar/global context from authoritative source;
- operational user story.

### Digital Public Good direction
Possible evidence:
- open-source licensing;
- open standards/data where possible;
- reproducible deployment;
- adaptable architecture.

### Scalability / real-world impact
Possible evidence:
- phone/edge architecture;
- vendor-neutral sensor abstraction;
- fleet aggregation path;
- clearly separated roadmap.

## Key principle

Do not create one slide per rubric item.

That produces a bureaucratic deck.

Instead, build a coherent story in which the same strong evidence satisfies multiple criteria.
