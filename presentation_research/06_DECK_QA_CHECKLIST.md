# Future Deck QA Checklist

The future PowerPoint is not finished until it passes both content QA and rendered-slide QA.

## A. Official constraints

- [ ] Main deck is 7–10 slides.
- [ ] Challenge 2 fit is unmistakable.
- [ ] Approach/methodology are represented.
- [ ] Open-source/DPG alignment is visible.
- [ ] Sustainability relevance is visible.
- [ ] No unsupported competition rule is invented.

## B. Story

- [ ] Each slide has exactly one primary message.
- [ ] Reading only the titles produces a coherent argument.
- [ ] The first 1–2 slides establish stakes and project thesis quickly.
- [ ] The demo occurs at a point where the audience already knows what to watch.
- [ ] Results/evidence appear before broad future-roadmap claims.
- [ ] Final slide leaves a specific remembered idea, not "Thank you" alone.

## C. Truth/evidence

- [ ] Every quantitative claim has a source/artifact.
- [ ] Implemented vs simulated vs future work is clear.
- [ ] Real dataset/model details match current artifacts.
- [ ] Hardware claims match physical verification status.
- [ ] No food-safety certification claim.
- [ ] No fake remaining-shelf-life/spoilage claims unless the final model actually validates them.
- [ ] No fabricated impact percentage.
- [ ] Reused/open-source work is credited.

## D. Text and typography

- [ ] No paragraph is used where the presenter should speak instead.
- [ ] Titles/assertions are roughly 36–48+ pt.
- [ ] Primary labels/body are roughly 24–30+ pt.
- [ ] No necessary text is below ~20–24 pt.
- [ ] Small citations are not required to understand the slide.
- [ ] No ultra-thin font weights.
- [ ] No all-caps body copy.
- [ ] Lines are short enough to scan quickly.

## E. Layout

- [ ] 16:9 widescreen.
- [ ] Critical content is not at the extreme bottom/edge.
- [ ] No accidental overlaps.
- [ ] No clipped text.
- [ ] No reversed/mirrored text.
- [ ] No floating panel covering another panel.
- [ ] Alignment is intentional.
- [ ] Consistent margins/grid.
- [ ] White space is preserved.
- [ ] No slide requires shrinking content to fit.

## F. Visual integrity

- [ ] Every visual has an information job.
- [ ] No generic AI brain/robot/network decoration.
- [ ] No glow/gradient fog/glass cards used merely for style.
- [ ] No dark navy/purple generic AI theme.
- [ ] Colors have semantic meaning.
- [ ] Actual project evidence is preferred to stock imagery.
- [ ] Screenshots are current and readable.
- [ ] Charts are presentation-redrawn, not notebook dumps.
- [ ] Charts have units and direct annotations.
- [ ] Contrast is at least 4.5:1 for normal text and 3:1 for large text as a floor.
- [ ] Meaning does not depend on color alone.

## G. Demo

- [ ] Live demo has a defined start/end state.
- [ ] Audience knows what to watch before switching away from slides.
- [ ] 30–60 second minimum proof path exists.
- [ ] Expanded science-fair demo exists.
- [ ] Deterministic replay exists.
- [ ] Screenshot/video fallback exists.
- [ ] Fallback demonstrates the same product, not a separate fake UI.
- [ ] Presenter can recover from failure without apologizing for two minutes.

## H. Rendering QA

- [ ] Opened in actual Microsoft PowerPoint.
- [ ] Full-screen slideshow reviewed.
- [ ] Exported PDF reviewed.
- [ ] Every slide visually inspected at full-slide view.
- [ ] Every animation/transition executed at least once.
- [ ] Fonts render correctly on presentation machine.
- [ ] Images are not blurry.
- [ ] No inaccessible external-linked asset.
- [ ] No missing video codec.
- [ ] Speaker notes are not exposed.
- [ ] Hyperlinks/QRs work if used.

## I. Audience-distance QA

- [ ] Review from several meters away or at reduced thumbnail scale.
- [ ] Main point remains obvious within ~5 seconds.
- [ ] Key number/trace is visible without reading tiny labels.
- [ ] Slide still works when presenter is speaking over it.
- [ ] Low-contrast secondary material does not vanish on projection.

## J. Anti-AI QA

- [ ] No slide looks like a generic template with nouns swapped.
- [ ] No meaningless card grids.
- [ ] No suspiciously verbose synthetic copy.
- [ ] No repetitive "Problem / Solution / Innovation / Impact" visual template without narrative.
- [ ] No invented icons/data.
- [ ] Visual language is specific to cold-chain evidence and this prototype.
